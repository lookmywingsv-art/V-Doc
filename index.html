Key Takeaways

四个关键判断

给管理层的四句话，每一条都对应一个具体动作。

01

Agent 会是下一个"电商 + 广告"的超级入口

种草、下单、投放，未来一个对话就能走完。ChatGPT 已经边卖广告边接支付，Shopify 接一次就铺满各大 Agent。TikTok 内容、商品、投放三样都有，这是我们最该抢的牌：把商品、素材、投放和转化数据一起接进 Agent，率先跑通"对话即成交"。

02

谁先被 Agent 想到，谁就赢

MCP 现在家家都有，决胜点是 Agent 能不能第一时间找到 TikTok、用好 TikTok。这就是 Agent 时代的 SEO：工具描述写清楚，数据做结构化，首发位和默认推荐全力争取，把"调用命中率"当北极星指标来运营。

03

分层推进 Agent 合作，客户统一沉淀到 Ads Manager

ChatGPT、Gemini 先完成标准接入，保证能被调用；Claude、Canva、Shopify、豆包推进深度集成，争取默认推荐和联合推广。Agent 里负责出方案、出草稿，最终确认、付款和精细调整回到 Ads Manager 完成，广告主账户和数据都留在 TikTok。

04

Q4 上线四个高频任务的"一句话 Skill"

目前能在 3P Agent 里直接投放的广告平台还不多。Q4 优先把建 Smart+ 计划、素材诊断、调整预算、生成周报做成广告主一句话就能完成的 Skill，配好花费上限和二次确认，用写操作占比和任务成功率衡量效果。

01 / 12工作正迁移到通用 Agent

看报表、做诊断、出素材、建计划，越来越多从一句话指令开始，而不是先打开 Ads Manager。中小企业用 AI 已是多数：据 Constant Contact 2026 年 Q1 对 5 国 1,500 多家中小企业的调研，54% 已在用 AI 营销工具，另有 27% 计划年内使用；最常见的用途是趋势分析（45%）、写内容（44%）和做图（40%）。

另一个入口是工作软件内置的 Agent。 Gartner 预测 2026 年 40% 的 SaaS 软件将内置任务型 Agent（软件里自带、只做特定任务的 AI 助手），2025 年还不到 5%。广告主很可能在每天用的软件里，直接通过内置 Agent 调用 TikTok。

场景一 · 电商卖家
在 Shopify 后台，一句话把新品投上 TikTok

商家问 Shopify 内置助手 Sidekick："这款新品怎么推？"Sidekick 先调出库存、毛利和近期销量，建议在 TikTok 投放；商家确认后，它直接调用 TikTok 建好 Smart+ 计划并关联商品目录，全程不用离开店铺后台。

场景二 · 市场或设计人员
在 Canva 做完视频，顺手投成 TikTok 广告

设计师用 Canva AI 做好一条 15 秒竖版视频后说："投到 TikTok，每天 50 美元，先跑一周。"内置 Agent 把素材推送到 TikTok、生成广告草稿，再引导回 Ads Manager 确认上线。

以上为基于现有产品能力推演的场景示例，具体功能以各平台实际上线为准。两个场景的共同点：广告主不用专门打开 TikTok，在日常使用的软件里就能完成投放。因此 TikTok 要尽早接入这些软件的内置 Agent。

交互也不会只停留在纯文字对话。 ChatGPT Apps SDK 和 MCP Apps 已经支持在对话里展示可交互的卡片、表格和图表。做得较好的有：Zillow 在 ChatGPT 里展示可拖动的房源地图；Instacart 生成可编辑的购物车，并支持在对话内付款（2025 年 12 月上线，是首个支持 Instant Checkout 的 App）；Hex、Amplitude 在 Claude 里展示可切换维度和时间范围的交互图表，与投放报表最接近。另一边，Google Ask Advisor、Amazon Ads Agent 把对话能力放进了广告后台。两种形态会相互融合（作者判断）。

02 / 12MCP 已成广告平台标配

MCP SDK 月下载量达 9,700 万（2026-05），Claude、ChatGPT、Gemini、Copilot Studio、Cursor 均已原生支持；2025 年 12 月，MCP 移交 Linux 基金会旗下的 Agentic AI Foundation，中立治理打消了平台方的顾虑。

  • MCP 不再是卖点。 广告主一句话就能对比 Meta 和 TikTok 的 ROAS，平台间的切换成本大幅降低。
  • 写权限和安全机制成为差异点。 Meta 新建计划一律暂停；Amazon 把多步操作合并为一句指令；Snap 允许按 Agent 分别授权。
  • 其他平台正陆续开放写权限。 Meta 7 月 16 日正式开放，9 月加入 Partnership Ads；Microsoft、Snap 已公开写权限路线，预计 6–12 个月内普及。
对 TT4B 的含义： 写操作要覆盖投放全流程、能串成完整任务；用默认暂停、花费上限、二次确认、按 Agent 授权来赢得信任；再用伙伴 Skills 加垂直方案，做竞品没有的工作流。核心指标看写操作占全部调用的比例。

与应用商店看似相似，实则有四点关键不同

  1. 工具由 Agent 来挑。 多数调用由模型根据任务语义匹配工具描述。比的是描述清晰、任务成功率高、响应快。
  2. 装了也不代表会用。 同一个 Agent 可同时接入多个广告平台，每次任务重新选择，留存靠每次都把事办成。
  3. 平台方也在做广告。 ChatGPT、Gemini 自营广告，合作中更要突出差异化价值，并做好多平台布局。
  4. 分发颗粒度在变细。 更多调用发生在一个 Skill 或工作流内部。

决定单 Agent MAA 的有三个变量：入口曝光（推荐位、默认 prompt、专区、模板）、授权门槛（Meta 已压缩到 5–7 分钟、无需 App 审核，是行业标杆）、首次任务效果。

⑤ 一次授权，多个 Agent 通用扩量

TikTok 可借鉴：一次授权后，广告主在 ChatGPT、Claude、豆包等 Agent 里都能直接用 TikTok，免重复配置，MAA 自然累加。

对 TT4B 的含义：MAA 的关键不只在上架数量，更在四个环节：能不能被主动调起、第一次能不能立刻出结果、能不能在对话里接着改、能不能顺畅回到 Ads Manager。建议把这四个环节分别设指标跟踪：调起率、首次任务成功率、多轮使用率、回流率。

Zynga · Alexa Skills

Zynga 2011 年占 Facebook 收入 12%，规则一改 FarmVille 月活从 8,000 万跌到 2,000 万。Alexa 技能第二周留存约 3%，69% 的技能评价数为 0–1 条。

成功案例的六条共性

  1. 把调用优先级当指标运营。 搜索时代赢家专门做 SEO；Canva、Context7 的工具描述清晰、功能聚焦。
  2. 重金押注默认位置。 Booking 大量买广告；Canva、HubSpot 每轮抢首发；Shopify 直接默认开启。
  3. 把流量沉淀为自有用户。 Booking 转会员和 App；Canva 回编辑器；Shopify 结账回店铺。
  4. 不押注单一平台。 Shopify、Canva、HubSpot 同时接入 ChatGPT、Claude、Gemini、Copilot 等多家 Agent；Zynga 只押 Facebook。
  5. 用公开数据建立信任。 Atlassian、Supabase 公开调用量和效果。
  6. 先解决曝光，再追求数量。 Alexa 技能多但用户找不到；成功案例先拿推荐位和高频场景。
为何不选其他类比
  • 微信小程序：靠社交裂变，Agent 里没有这种传播链。
  • App Store：靠用户主动搜索安装，而 Agent 里多数调用由模型自动选择。
  • 支付网络、header bidding（程序化广告竞价）：更像协议之争，只能解释局部现象。
10 / 12策略主线与四个抓手

贯穿各方向的四个核心抓手

这不是新增任务，而是五个方向共用的方法。资源有限时优先保证这四项，重点看两个指标：分 Agent 的任务成功率、写操作占比。

1 · 让 Agent 优先调用 TikTok

工具名称和描述用广告主原话写（"看 TikTok 广告效果""建 Smart+ 计划"）；工具少而精；建一组测试问题，按 Agent 定期测试命中率。

2 · 抢占默认入口

争取首发合作、starter prompt、模板、行业专区。每个新入口（Claude Marketplace、ChatGPT 插件目录、WorkBuddy Buddy 应用）都争取首批上架。

3 · 一键授权，首次使用即成功

Meta 已做到 OAuth 登录即用、无需开发者凭证，Amazon 仍限 API 伙伴，这是拉开差距的机会。用 Skills 打包高频任务，首次使用就能出结果。

4 · 用安全机制赢得写操作信任

新建默认暂停、花费上限、二次确认、按 Agent 授权；写操作要能串成完整任务，而不是零散的单点接口。

五个重点方向

  1. 覆盖：通用与工作流 Agent 并重。 通用 Agent（ChatGPT、Gemini、Claude、Copilot、豆包）决定覆盖上限，先保证接入；工作流 Agent（Canva、Shopify、Mailchimp、Wix、GoDaddy Airo）意图更明确，优先深度集成。组合示例：Canva 生成素材 → TikTok MCP 一键建 Smart+ 广告 → 在 ChatGPT 或 Claude 看报表调预算。
  2. 使用：从上架走向默认调用。 可发现 → 低摩擦授权 → 首次使用成功（如查看昨日花费）→ 形成习惯（每周报表）。
  3. 效果：用 Skills 把高频任务封装成一句话指令。 从创建 Smart+ 广告、素材诊断、预算调整、周报四类开始。
  4. 投入：按边际 MAA 分配资源。 按"投入后预计新增 MAA ÷ 投入资源"排序，避免平均用力（见下图）。
  5. 信任：权限与花费安全。 按 Agent 粒度授权、可随时撤销；预算类写操作设上限和二次确认；操作留痕可查。

对 TT4B 的五点启示

  1. 像做 SEO 一样运营 Agent 调用。 用测试问题集定期测试命中率，据此优化工具描述。
  2. 争取首发和默认推荐，做到免配置。 每个新入口都争取首批上架，首次授权后无需任何配置。
  3. 多平台均衡布局。 重点深耕相对中立的 Agent（Claude、Kimi、Manus、Perplexity）和豆包，坚持支持开放协议（MCP、Skills）。
  4. 把用户引回 TikTok Ads Manager。 Agent 生成方案和草稿，确认、付款和精细调整回到 Ads Manager，把 Agent 流量沉淀为自有广告主。
  5. 公开使用数据。 参考 Atlassian，定期对外公布 MCP 月活、调用量和效果案例。

方法。 以公开资料为主，内部数据仅用于描述 TT4B 现状。整理 2025-10 至 2026-10 各广告平台官方 MCP、自有 Agent 与协议的发布信息，以平台公告或行业媒体为准，日期不一致时取首次公开可用日期。标杆案例按公开披露的用户量、调用量和可归因收入综合排序，未公开的部分不做估算。历史类比从"平台是否兼做广告、选择机制、默认位置价值、赢家如何留住用户"四个维度比较。展望阶段与形态占比趋势为作者判断。
